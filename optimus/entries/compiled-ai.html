Summary

A company systems paper: LLMs generate code artifacts at compile time, after which orchestration runs deterministically, and semantic steps become bounded LLM tool calls whose schema and trigger are fixed at compile time (the 'Code Factory' variant). Evaluated on BFCL function calling (n=400) and DocILE invoices (n=5,680), with a released 540-specification benchmark suite, targeting healthcare administrative workflows such as prior authorisation.

Our take

The closest commercial statement of our thesis, from a funded company in the same first market. Its limitations section names bounded-tool-call drift monitoring and continuous re-optimisation as unbuilt future work, which is both validation and a sign it is a race.

Key numbers

  • 96% task completion on BFCL with zero execution tokens; break-even with runtime inference at ~17 transactions; 57× fewer tokens at 1,000 transactions (author-reported)
  • DocILE: Code Factory KILE 80.0% (matching Direct LLM) and LIR 80.4% (best), at 2,695 ms against 6,339 ms for Direct LLM (author-reported)
  • Pure deterministic regex: 20.3% KILE (author-reported)
  • TCO at 1M transactions/month $555 against $22,000 (author-reported)
  • 4% compilation failure (16/400 BFCL); generated code cyclomatic complexity 23.8 against 8 for human code (author-reported)
